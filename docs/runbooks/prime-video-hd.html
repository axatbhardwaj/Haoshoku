Prime Video HD SD — broke 2026-06-25 Wine · Bottles

Windows Brave under Wine-TkG, on CachyOS / Hyprland — runbook & rationale. Generated 2026-06-23; status update 2026-06-26.
⚠ STATUS — broke 2026-06-25. This 1080p path stopped working. Amazon deployed a server-side Wine/VM detection change (~June 25, 2026) that defeats the mechanism this bottle relied on. Crucially, the 1080p here was not Widevine L1 or HDCP hardware — it was VMP (the Windows Widevine CDM's signed Verified Media Path certificate, which Amazon's policy trusts for HD while it caps native Linux to SD). With VM detection on, the bottle is treated like untrusted Linux, so the encrypted feature now plays SD (≈540p). The same break hit all prime-wine users the same day (issue #4 + Winboat). Not recoverable by any client-side config as of 2026-06-26 — GPU-enabled, UA override, and a fresh profile all stay SD (POC + evidence: ~/superpowers/prime-hd-poc/). HD now requires a real Windows environment (VFIO GPU-passthrough VM), a community detection-bypass (none confirmed yet), or dedicated HDCP hardware (Fire stick / smart TV / Windows PC). Everything below describes the setup as it worked before the break.
TL;DR. Amazon throttles Prime Video on Linux (native Brave here = 540p). Running Windows Brave under Wine-TkG 10.8 (via Bottles) used to get the full 1080p by presenting the Windows VMP-certified Widevine CDM, but that path broke on 2026-06-25. Launch as “Prime Video HD” (or Super+Shift+P) only if you accept current SD playback; fullscreen no longer restores HD.

First-time setup (build the bottle)

On a machine without the bottle yet, the primevideo-setup helper does the heavy lifting; two steps stay manual (Bottles' component bootstrap is GUI-only, and the Amazon sign-in is yours). The helper is idempotent — re-run it freely.

1 · Run the helper

primevideo-setup        # deployed to ~/.local/bin by Haoshoku

Fetches the Wine-TkG 10.8 runner and — once the bottle exists — sets its runner + Win10, installs Brave 1.91, and writes the primevideo-hd launcher.

2 · manual Create the bottle (Bottles GUI)

If the bottle is missing, the helper stops and asks for it. In Bottles, create a new bottle, then re-run primevideo-setup:

Name:        primevideo-tkg9
Environment: Application   (any default runner — the helper swaps it)

3 · manual First launch + sign in

Launch with Super+Shift+P (or ~/.local/bin/primevideo-hd). In Brave: sign into Amazon, accept the Widevine prompt, keep Shields OFF for primevideo.com, and play a title. Expect SD unless Amazon's server-side Wine/VM detection changes again.

Recipe lives in configs/scripts/primevideo-setup. On a machine that already has the bottle, a re-run just verifies and no-ops.

How to launch

1 · Keybind (normal use)

Super+Shift+P → toggles its own special:primevideo workspace (like Spotify) and launches Prime if not already running. This is currently an SD fallback, not an HD launcher.

2 · App launcher

Run “Prime Video HD” from the Caelestia/Hyprland launcher (same toggle behavior).

3 · Terminal

~/.local/bin/primevideo-hd

Launch flags baked into the launcher (all required — see "How we got here"):

--app=https://www.primevideo.com
--disable-gpu                          # NVIDIA Vulkan-WSI blank-window fix
--disable-accelerated-video-decode     # avoids D3D11 video-buffer crash
--disable-gpu-memory-buffer-video-frames

ZEE5: the same bottle also serves ZEE5 — Super+Shift+Z → special:zee5 (launcher ~/.local/bin/zee5-hd; the two Wine-Brave windows are told apart by initial_title). Whether the bottle beats native Brave for ZEE5 is unconfirmed — ZEE5 may gate HD on Widevine L1 (hardware), which Wine can't provide.

How we got here (and the 720p red herring)

Getting Brave to run Prime under Wine took three real fixes. Before Amazon's 2026-06-25 server-side change, the bottle did reach real 1080p through the Windows VMP path. The current SD cap is a new break, not the original viewport-size mistake.

SymptomCauseFix
Blank white windowDXVK can't make a Vulkan swapchain (NVIDIA + XWayland)--disable-gpu
Hard crash on Play (system Wine 11.11)Prime uses PlayReady → unimplemented WinRT in Wine 11.11runner = Wine-TkG 10.8
Crash entering the video pipelineD3D11 GPU video-frame buffer under Winesoftware-video flags
"Only 720p" pre-breakmeasured in a windowed player — viewport-limited, not a DRM capfullscreen reached 1080p before 2026-06-25
Detour worth noting: chasing the phantom 720p cap, we tried Brave 1.82 (to force Widevine). It won't run on any Wine here (a UISettings WinRT recursion → stack overflow). Turned out irrelevant to the old path — Brave 1.91 + TkG 10.8 did 1080p before Amazon's server-side break. The 1.82 path was abandoned and its artifacts cleaned up.

Troubleshooting

Only getting SD / 720p (not 1080p)

That is the expected state after the 2026-06-25 server-side Wine/VM detection change. Fullscreen no longer restores HD in the bottle. See ~/superpowers/prime-hd-poc/ for the CDP evidence and experiment matrix.

Window is blank / white

GPU path failed; --disable-gpu (already in the launcher) fixes it.

Crashes the instant you press Play

You're on the wrong runner. The bottle must use Wine-TkG 10.8 (wine-10.8-staging-tkg-amd64), not system Wine 11.11.

Asks me to log in again / quality drops

Login lives in the bottle's Brave profile — sign in once, it persists. Keep Brave Shields OFF for primevideo.com (already set).
