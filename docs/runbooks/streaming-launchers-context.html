Brave App-Mode Launchers on Hyprland

Context for the five chromeless app launchers — CachyOS / Hyprland / Caelestia, managed by Haoshoku (v5.9.9). Generated 2026-06-25.
Prime Video · Wine bottle ZEE5 · native + selector Crunchyroll · native JioHotstar · native WhatsApp · native
TL;DR. Five chromeless app windows — four streaming (Prime, ZEE5, Crunchyroll, JioHotstar) plus WhatsApp Web — each pinned to a workspace and a keybind. Prime needed a Windows-Brave Wine bottle for 1080p (Linux is throttled) — but Amazon broke that ~2026-06-25 (server-side Wine/VM detection; see the Prime note below), so it now plays SD too; everyone else runs in native Linux Brave. Windows route to workspaces by their app-id class, so they never collide. Every native launcher now lives in its own dedicated Brave profile (~/.local/share/<app>-brave-profile) — isolated from your personal Default profile and from each other.

2 · How a keypress becomes a routed window

The dedicated --user-data-dir does not change the class — the suffix comes from --profile-directory=Default, so the window class (and therefore routing) is identical whether the profile is shared or isolated.

3 · Two engines, and the profile model

🍷 Wine bottle — Prime Video only

Amazon throttles Prime on Linux to 540p. A Windows-Brave bottle (Wine-TkG 10.8) presented a "Windows" client (a VMP-certified CDM) and used to unlock 1080p — but Amazon's ~2026-06-25 server-side Wine/VM detection broke that, and it now plays SD like native. (VMP policy, never L1/HDCP.) Built by primevideo-setup.

Software-rendered to dodge the NVIDIA Vulkan-WSI blank window; Prime tolerates that.

🦁 Native Brave — everyone else

ZEE5, Crunchyroll, JioHotstar, WhatsApp run in native Linux Brave — it has real hardware acceleration, which these players require. The bottle cannot give them that here (Wine lacks WGL_NV_DX_interop2; Vulkan WSI fails; no Media Foundation).

See the findings: ~/zee5-bottle-hwaccel-findings.html.

Profile isolation. Each app gets its own profile so logins, cookies, and history never mix with personal browsing or each other:
  • Prime — the Wine bottle is the profile (Amazon sign-in lives inside the bottle).
  • ZEE5 — isolated ~/.local/share/zee5-brave-profile, seeded from Default (the CDP Full-HD automation needs the login already present).
  • Crunchyroll / JioHotstar / WhatsApp — isolated, fresh (no seeding): a clean profile created on first launch, so you log in once per app (WhatsApp = one QR scan). This keeps them reproducible and uncoupled from your Default profile's cookie clears.

6 · Adding another service

The native pattern (CR/JioHotstar/WhatsApp) is the template. For a service that plays acceptably in native Linux Brave:

1. Probe the real window class once:
   brave --profile-directory=Default --app=https://www.SERVICE.com &
   hyprctl clients -j | jq '.[]|select(.initialTitle|test("SERVICE"))|{class,initialTitle}'
   # -> class brave-www.SERVICE.com__-Default, initialTitle www.SERVICE.com_/

2. configs/scripts/SERVICE-hd      (clone crunchyroll-hd; set URL + a dedicated
                                    --user-data-dir=~/.local/share/SERVICE-brave-profile)
3. configs/caelestia/cli.json      (add the toggle: class brave-www.SERVICE.com__-Default)
4. configs/caelestia/hypr-user-pc.conf
      windowrule = workspace special:SERVICE, match:class brave-www\.SERVICE\.com__-Default, match:initial_title www\.SERVICE\.com_/
      bind = Super+Shift, KEY, exec, caelestia toggle SERVICE   # check the chord is free: hyprctl binds
5. configs/mimeapps/applications/SERVICE-hd.desktop   (clone, set StartupWMClass)
6. Add tests (mirror the CR/JioHotstar tests), bun test, then deploy + caelestia toggle to verify.

The dedicated --user-data-dir keeps the class as ...__-Default, so routing is unaffected — only the profile (and login) is isolated. If the service won't hit 1080p natively and needs the quality forced, port ZEE5's CDP selector. The Prime-style Wine bottle used to help when a Windows VMP-certified CDM unlocked an HD tier, but Amazon's ~2026-06-25 Wine/VM detection broke that path; do not assume it restores HD for new services.
